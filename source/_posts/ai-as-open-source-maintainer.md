## 一、读 Armin 那篇，我卡在"自信的错"上

Armin Ronacher（Flask 的作者）五月发了篇关于维护 Pi 这个开源项目的随笔，里面有一段我读了两遍：

> 现在有一种 issue，是 5% 人写的、95% 是 agent 生成的，而且大多数是错的。一个带着"貌似合理但实际错误"的诊断的 issue，比没有诊断更糟。

他说他给维护 agent 写了一条 slash 命令，专门要求"不要相信 issue 里写的分析，自己从代码和执行路径独立推导"。但没用——**因为 agent 会把这个 issue 当成证据，不是当成谣言**。它顺着里面那段自信但错误的诊断往下走，走得还挺顺。

我卡在"自信的错"这五个字上。

因为我自己的项目也在接 LLM 帮人写的东西。我写的那些"请你试 X 然后贴回"的诊断清单，本质上是在邀请用户把问题丢给一个 agent，让 agent 替我"理解、复现、定位、给方案"。我现在开始怀疑：**我最怕收到的不是空 issue，是一份 agent 写得很像那么回事、但根因是猜的复现报告。** 它会让我的维护 agent 走错方向，而且错得很顺。

## 二、他说"本地防御"是错的，我同意但没做到

他第二段的核心观点很狠：

> 几乎所有时候，正确的修法不是去处理坏状态，而是让坏状态不可能出现。

他举的例子是 Pi 的 session log 有一组必须守住的不变量，但 agent 一看到"这个畸形日志让 reader 崩了"，就本能地加宽容的 reader、加 fallback、加迁移、加一堆测试。"每一处单独看都没错，合起来对这个系统就是错的。"

他说维护者的活儿，就是不停地把对话拽回那个全局不变量上，**而这比它应有的难度难得多，还很累。**

我读这段的时候有点难堪。因为我在自己的项目里干过一模一样的事——为了"防御某个脏输入"在边界上加了一整层校验，把数据流弄得更复杂，而不是去上游保证那个脏输入根本不会写进来。我加的是本地防御，他守的是全局不变量。

**他说的"拽回全局不变量很累"，其实是我懒得做的那件事的体面说法。**

## 三、"量"本身成了维护成本

他给了 Pi 近 90 天的数据：3145 条外部 issue/PR，2504 条因为不是"已批准的人"被自动关掉，最终被重开修掉的只占 17%，算上被合并 PR 引用的也就 26%；PR 更惨，714 条里只有 60 条被合并，**约 8%**。

我没打算把这套数字套到自己头上——那是 Pi 的处境，不是我的。但它戳中了一个我绕不开的点：

**我维护的东西，"吞吐量"本身已经成了成本。** 不是"要修几个 bug"，是"要分诊多少个由机器写、我根本没主动要的东西"。我甚至开始分不清哪些 issue 是真人提的、哪些是某个 skill 顺手丢进来的。他说的"有些垃圾连提 issue 的机器自己都没意识到自己在制造垃圾"，这一句我没法反驳。

## 四、他说"隔离不是开源的价值"，我上周正好反着活

他收尾那段，是我读完最受刺激的一段：

> AI 没有增加需要软件的人，也没有增加能 review 代码的维护者。它主要增加的是代码量和争抢注意力的项目数。……人是很难跟人沟通的，而当你可以一个人窝着你的 agent 时，逃避这种沟通就太诱人了。但**孤立不是开源价值的来源。价值在社区，在让项目能活过它的原作者的那些结构里。**

我读到这里愣了一下，因为我之前写的那篇 [《不混用了吗》](/2026/09/24/independent-project-boundary-principle/) 讲的方向，跟他这句话正好对着。

他讲的是"别一个人窝着 agent 绕开本地问题，去找上游、去跟人沟通"。我讲的是"不同领域的应用必须是独立项目，别把文档转换接口塞进商城后端"。表面看一个要"往上游靠"，一个要"把边界切干净"，**其实是同一件事的两面：都在说"你下意识想省掉的那一步，恰恰是价值所在"。**

他省掉的是跟人沟通的那一步，我差点省掉的是划清边界的那一步。AI 让我俩都太容易"就地解决"，而"就地解决"在 Armin 眼里是腐蚀，在我眼里是越界。

## 五、我不打算下结论的事

Armin 那篇是维护者的自白，我这篇是读者的回信。我能确定的只有一件事：

**我写诊断清单、写"请贴回 X 输出"的时候，应该假设用户会把这段丢给 agent，然后让 agent 替我写回一份自信但可能是错的复现。** 所以我的清单应该短到"机器没法把它膨胀"——只列事实（命令、预期、实际、日志），把"分析和根因"留给能读代码的人（包括我自己），不外包给那个会把范围越弄越大的 agent。

我上周那篇《不混用了吗》里"把边界切干净"的冲动，可能也是同一个病：**图省事地就地解决，而不是去找那个更麻烦但更对的上游。**

这两件事我都没准备好马上改。我在这篇文章里写下的，不是决定，是承认。

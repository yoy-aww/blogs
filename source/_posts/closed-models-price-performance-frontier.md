## 一个直接打脸我的标题

阮一峰周刊第 420 期推荐了一篇文章，标题我读了三遍才放下：

> "几乎在每个预算下，你能买到的最好的模型，都是闭源的。开源权重模型只在 3% 的价格点上胜出——6 月还是 41%。"

写这句的是 [Village](https://village.dev/blog/closed-ai-models-now-dominate-the-price-performance-frontier/) 的 Kevin Hu，他用一个叫 LLM Atlas 的工具，把每个价位上能力最强的模型连成一条"价格-性能前沿线"。结论就一句话：**开源的性价比领先是脉冲式的，每次都持续不到一个季度，然后被闭源的新低价打回去。**

我第一反应是：这说的不就是我吗？

我一直用本地 Ollama，Qwen3、R1、llama3 轮着跑，拒绝付费 API。我以为自己是"站在开源这边"的人。

第二反应是：我得诚实一点。这篇文章没冤枉我，它只是量了我没量的东西。

## 文章说的是"买 API"的账，不是我的账

先把话说清楚——文章作者自己标注了那条最关键的限制：

> "成本反映的是评估者通过托管 API 支付的价格。开源模型在自己的硬件上跑可以更便宜。"

这句话被埋在"How we built this"那一节，但它是整篇文章对我的全部意义。前沿线量的是**买 API 的性价比**，不是**自己掏钱买显卡、自己付电费、自己写部署脚本的性价比**。

我的"免费"方案不是免费的。它只是把成本换了个位置：

- 我的 12GB 显卡是真金白银买的，R1 在它上面跑不出闭源旗舰的能力
- 我的 Qwen3 能做工具调用，但 R1 当年干脆没有 tool calling——我在博客里记过这个坑
- 每次本地部署的排障时间，都是我自己出的

所以文章说"闭源赢在每个价位"，严格讲它赢的是**用别人的服务器**这个价位。我用的是自己的硬件——这不在这条线上。

## 闭源为什么赢，机制的三个解释我是认的

文章给了三个解释，我认为都成立，而且值得记：

1. **闭源能自己蒸馏自己。** 有最强旗舰的实验室，可以用旗舰的输出训练便宜档。Claude Haiku 5.5 在 Opus 5.5 之后两周就出了。开源实验室只能从自己更弱的模型出发——因为闭源条款普遍禁止拿它们的输出训练竞品。
2. **闭源出全家桶。** OpenAI 的 GPT-6 和 GPT-6.1 一个家族就占了前沿线 21 个点里的 11 个，一代覆盖几乎每个价位。
3. **闭源规模更大，单任务成本更低。** OpenAI、Anthropic、Google 的运行规模摆在那，Google 还用自己的芯片。

这三个机制我挑不出毛病。它们说明一个我早该承认的事实：**"开源更便宜"从来不是定律，只是一个随时会被打穿的市场缝隙。**

## 然后我要戳自己一下

我拒绝付费 API，到底有多少是"本地免费"的信念，有多少是"不想掏钱"的抠门？

如果前沿线真的是对的——每个价位上闭源都更强——那我的本地方案在**纯能力**上确实输了。我拿"数据不出门""可控性""能改权重"给自己找台阶。可我冷静看看自己实际在跑什么：**翻译一本书、写博客、抓周刊选题、RAG 检索。** 全是公开数据、公开输出。

隐私论据对我不成立。我根本没在跑什么需要保密的东西。我在为一条我不完全需要的理由，付一笔我还没算清的账。

## 那我的"预算"到底是什么

想了两天，我觉得我不该跟文章争"谁更强"——那场仗我打不赢，前沿线是拿数据说话的。

我真正该问的是：**我的预算单位不是钱。** 对文章里的评估者，预算单位是"每个任务花多少钱"。对我，预算单位是：

- 我愿不愿意让数据经过别人的服务器（答案：目前没什么不能过）
- 我愿不愿意为一次 API 调用排队、限流、看它被模型公司改价（答案：很烦）
- 我愿不愿意为一个工具链写一个能本地跑的替代（答案：写的时候很爽，维护的时候想死）

最后一条最讽刺。我"本地免费"的快乐，很大一部分来自**把别人的问题变成我的工作**。

## 我不打算在这篇里下决定

我不打算说"我从此全用闭源 API"，也不打算说"本地永远是对的"。

我大概率会继续用本地模型——不是因为它更强，是因为**它让我在写代码和调部署的时候，感觉自己真的在动手**。这种感觉对我的价值，不在 LLM Atlas 的坐标轴上。

但我会记得一件事：我所以为的"站在开源这边"，其实站的是一个特定的成本结构。哪天我的数据真的不能过别人的服务器了，或者哪天我算明白那笔排障时间比 API 账单还贵，我这两边的账要重新算。

那时候我希望自己别再拿"本地免费"四个字糊弄自己。
